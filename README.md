# set-up-development

Переносимый скилл для настройки репозитория под агентскую разработку в **Codex**.
Он переносит рабочие соглашения: инструкции проекта, роли `worker` и `scout`,
27 инженерных скиллов, локальные задачи и Graphify. При применении к существующему
проекту агент адаптирует шаблоны и сохраняет его настройки.

## Использование в Codex

Склонируйте пакет в удобное место:

```bash
git clone https://github.com/NiP22/set-up-development.git
```

В чате целевого проекта передайте абсолютный путь к `SKILL.md` и запрос:

> Используй скилл set-up-development из /path/to/set-up-development/SKILL.md.
> Подготовь этот репозиторий к агентской разработке. Сохрани существующие настройки.

Для постоянной установки можно скопировать **весь каталог** пакета в
`~/.agents/skills/set-up-development` и открыть новый чат проекта, затем вызвать
`$set-up-development`. Один `SKILL.md` без `assets`, `scripts` и `references`
не содержит всего необходимого для установки.

## Прямое применение к новой папке

Нужны Python 3.11+, Git, Bash и файловая система с поддержкой символических ссылок.
Проверено на Linux; Windows без Bash и поддержки symlink не проверялся.

```bash
# Показывает план, не создаёт файлов.
python3 /path/to/set-up-development/scripts/bootstrap.py /path/to/project

# Создаёт недостающие файлы и относительные ссылки после проверки конфликтов.
python3 /path/to/set-up-development/scripts/bootstrap.py /path/to/project --apply
```

Повторное применение одинакового набора ничего не меняет. При любом конфликте
скрипт возвращает код 2 до записи файлов. Для существующего проекта используйте
скилл: агент объединит нужные правила с текущими файлами. Сам скрипт не объединяет
TOML или Markdown и не имеет режима принудительной перезаписи. Ошибка ОС во время
записи может оставить уже созданные новые файлы; транзакционного отката нет.

## Что появляется в проекте

| Путь | Назначение |
|---|---|
| `AGENTS.md` | Работа с кодом, проверки, делегирование, указатели на документацию |
| `.codex/config.toml`, `.codex/agents/` | Роли `worker` и `scout` |
| `docs/agents/` | Локальные задачи, triage, словарь и ADR по необходимости |
| `docs/skills/mattpocock/` | 27 скиллов, исходная лицензия и сведения о версии |
| `.agents/skills/` | Относительные ссылки на установленные скиллы |
| `scripts/setup_graphify.sh` | Настройка закреплённого Graphify |
| `.gitignore`, `.graphifyignore` | Локальные артефакты и исключения из графа |

Модели в шаблоне: `worker` — `gpt-6.1-sol/high`, `scout` — `gpt-6-luna/medium`.
Это настройки исходного окружения; перед использованием проверьте доступность
моделей в своём аккаунте и измените роли при необходимости. Основную модель чата
шаблон не задаёт. Формат ролей описан в [официальной документации Codex](https://learn.chatgpt.com/docs/config-file/config-reference).

## Graphify

Graphify — отдельный инструмент разработчика, **не Python-зависимость приложения**.
Закреплена версия `graphifyy==0.9.79`; автоматического обновления до latest нет.
Если инструмент ещё не установлен, установите через `uv`:

```bash
uv tool install 'graphifyy==0.9.79'
```

Если другая версия уже используется другими проектами, сначала выберите способ
сосуществования или согласуйте замену. Затем в целевом проекте:

```bash
# Только для новой папки, если локального репозитория ещё нет.
git init -b main

bash scripts/setup_graphify.sh
```

Скрипт устанавливает проектный скилл Graphify, hooks `post-commit`/`post-checkout`
и merge driver, дополняет `.gitattributes`, затем строит структурный граф кода и
Markdown без LLM-вызовов. Существующие пользовательские hooks сохраняет штатный
установщик Graphify; alias Git не меняется. Готовый граф не копируется из пакета.
В пустом проекте индекс содержит только добавленные документы, не будущий код.

`graphify-out/` и генерируемый скилл Graphify остаются локальными. Конфигурация
ролей, исходники инженерных скиллов и относительные ссылки предназначены для Git.
После обычного pull/merge, rebase или cherry-pick обновите индекс:

```bash
PYTHONHASHSEED=0 graphify update .
graphify hook status
graphify query "имя реального символа или заголовка" --budget 1500
```

Подробности инструмента: [Graphify](https://github.com/Graphify-Labs/graphify).
Семантическое обогащение — отдельная операция, базовая настройка его не запускает.

## Проверка и изменения пакета

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют установку, повторное применение, сохранение существующих файлов
и защиту от записи через чужие symlink-пути. Изменения установщика сопровождайте
тестом наблюдаемого поведения. Сторонние скиллы обновляйте отдельно, сохраняя
лицензию, исходную ревизию и проверяя изменения их поведения.
