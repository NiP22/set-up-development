# Предметная документация

Перед исследованием или проектированием прочитай `docs/GLOSSARY.md` и относящиеся
к задаче решения в `docs/adr/`, если они существуют. Сохраняй принятую в проекте
структуру предметных областей; не вводи новые границы без конкретной причины.

- `docs/GLOSSARY.md` хранит согласованные термины и краткие определения.
- `docs/adr/NNNN-slug.md` хранит существенные решения и причины выбора.
- `docs/tasks/` хранит задачи, спецификации и обсуждения; порядок описан в
  [issue-tracker.md](issue-tracker.md).

Создавай эти файлы по мере появления содержания. Словарь не заменяет спецификацию.
ADR нужен, когда решение трудно обратить, неочевидно следующему читателю и принято
после выбора между альтернативами. Простые обратимые решения достаточно записать
в задаче. Конфликт с действующим ADR обозначай явно.

Новые предметные термины и ADR оформляй через `domain-modeling`. Общие ссылки
скиллов на корневой `GLOSSARY.md` здесь означают `docs/GLOSSARY.md`, а `.scratch/`
означает `docs/tasks/`. Существующие правила проекта имеют приоритет над шаблоном.
