# Локальные задачи

Задачи и спецификации проекта хранятся в Markdown внутри `docs/tasks/`.
Это локальный issue tracker: команды скиллов «publish to the issue tracker»
и «fetch ticket» означают запись и чтение этих файлов.

## Размещение

- Одна тема: `docs/tasks/<feature-slug>/`.
- Спецификация: `docs/tasks/<feature-slug>/spec.md`.
- Каждая задача — отдельный файл:
  `docs/tasks/<feature-slug>/issues/<NN>-<slug>.md`, нумерация с `01`.
- Роль triage указывается строкой `Status:` в начале задачи;
  значения определены в [triage-labels.md](triage-labels.md).
- Зависимости: `Blocked by: NN, NN`. Условия завершения и результат
  фиксируются в самой задаче; роль triage сама по себе не означает завершение.
- Обсуждение дописывается в раздел `## Comments`.
- Ссылки на задачи ведут на их файлы; номера трактуются внутри одной темы.

Каталоги и файлы создаются по необходимости. Для небольшой согласованной
правки отдельная спецификация и набор задач необязательны.
Входящие обращения проходят triage; задачи, уже подготовленные через
`to-tickets`, сразу используются для реализации.

## Карта решений wayfinder

Если используется `wayfinder`, карта находится в
`docs/tasks/<effort>/map.md`, а дочерние решения — в `issues/NN-<slug>.md`.
Тип задаётся строкой `Type: research | prototype | grilling | task`;
состояние работы — отдельной строкой `Decision state: open | claimed | resolved`.
Это состояние решения отдельно от `Status:` triage.

Доступно решение со состоянием `open`, у которого все `Blocked by`
имеют `Decision state: resolved`. Выбирается первый номер.
Перед работой записывается `claimed`; при завершении — `resolved`,
ответ в `## Answer` и краткий указатель на него в карте.

## Переопределение общих примеров скиллов

Примеры `.scratch/<feature>/` заменяются на `docs/tasks/<feature>/`.
Прочие новые Markdown-артефакты агентов также размещаются внутри `docs/`.
Публикация во внешнем tracker для этого проекта не настроена.
