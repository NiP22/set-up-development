# Работа с проектом

## Реализация и проверка

- Перед правками прочитай затрагиваемый код и инструкции. Выбирай решение,
  соразмерное задаче; дополнительные слои и зависимости обосновывай требованием.
- Сохраняй чужие изменения и окружающий стиль. Существенные изменения поведения
  согласуй; обычные обратимые решения принимай по соглашениям проекта.
- Для SDK сначала проверь штатные методы и пример из официальной документации
  подходящей версии. Не дублируй встроенную валидацию, retries и lifecycle.
- Определи наблюдаемый результат. Команды проверки бери из манифестов и
  документации этого проекта. Заверши необходимые проверки и разбери сбои.
- Сообщай кратко: результат, проверка, ограничения. Отделяй факты от предположений.

## Сабагенты

Используй сабагентов, когда независимые подзадачи заметно ускоряют работу или
повышают качество. Простые задачи выполняй самостоятельно. Настройки находятся
в `.codex/config.toml` и `.codex/agents/`:

- `worker`: реализация, сложная диагностика, архитектурный анализ и ревью.
- `scout`: точечный поиск и извлечение фактов со ссылками; без изменений файлов.

Задавай границы задачи и ожидаемый результат, разделяй запись по файлам.
Принимай итог сам. Модели ролей должны быть доступны в текущем окружении.

## Скиллы и документация

Скиллы находятся в `.agents/skills/`. Их исходники и лицензия — в
`docs/skills/mattpocock/`. Если скилл просит вызвать недоступный `Skill tool`,
прочитай `SKILL.md` указанного скилла и следуй ему напрямую. Если его нет,
сообщи об отсутствии, не подменяя предполагаемым поведением.

- Перед созданием или выполнением локальной задачи прочитай
  [issue-tracker.md](docs/agents/issue-tracker.md).
- Перед triage прочитай [triage-labels.md](docs/agents/triage-labels.md).
- Перед предметным исследованием, проектированием или записью решения прочитай
  [domain.md](docs/agents/domain.md).
- Новые исследовательские заметки, планы и отчёты размещай в `docs/`.
  Обязательные файлы инструментов (`AGENTS.md`, `SKILL.md`, `README.md`) оставляй
  там, где их ожидает соответствующий инструмент.

## Graphify

Версия CLI закреплена в `scripts/setup_graphify.sh`; перед первым использованием
в сессии сверь `graphify --version`. Для архитектуры, зависимостей и влияния правок
используй существующий `graphify-out/graph.json`, затем подтверждай выводы кодом.
Для известного файла достаточно прямого чтения и `rg`.

Из корня проекта:

- `graphify query "символ или тема" --budget 1500` — ближайший контекст.
- `graphify query "тема" --dfs --budget 1500` — цепочки связей.
- `graphify explain "узел"`, `graphify path "A" "B"` — связи конкретных узлов.

Подбирай реальные имена. При нерелевантном результате уточняй запрос или переходи
к `rg`. Пустой граф не заменяет чтение исходников. После pull/merge, rebase,
cherry-pick или при отставании индекса выполняй `PYTHONHASHSEED=0 graphify update .`.
Hooks обновляют структуру после commit/checkout; в linked worktree обновляй вручную.

Граф локальный, не является исходником или общей памятью. Личные результаты
`graphify save-result` сохраняй с `--memory-dir graphify-out/private-memory`:
в 0.9.79 стандартный `memory/` попадает в индекс вопреки ignore-правилам.
Семантическое обогащение выполняй отдельно через скилл `graphify`, когда оно нужно.
